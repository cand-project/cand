# P0.3 IMPLEMENTATION REPORT

## Base main

Base: `d47e557` (P0.2 merged main).

## ARCHITECTURE

- `ObjectId`: deterministic per-function allocation-site identity (`obj:N`).
- `StorageId`: AST-derived local, field-path, and full constant-array-index-path identity, with reserved future dereference-slot support.
- `PointerRelation`: `Owner`, `Alias`, `Null`, `MaybeNull`, `Unknown`.
- `ObjectInfo`: authoritative object state, allocation, and destruction metadata.
- `FlowState`: independent object table plus storage-to-object bindings.
- ambiguous targets use a distinct sentinel and can never be confused with `NULL`.

## NEWLY SUPPORTED

Local aliases and reassignment, local struct members including nested paths,
constant-index pointer arrays including multidimensional paths, aliases through
those storages, CFG alias joins where the target is soundly representable, and
pointer arithmetic through aliases. Casts that Clang reduces to the same
pointer storage remain supported. Destruction is object-wide.

## FAIL-CLOSED BOUNDARY

P0.3 intentionally remains `INCOMPLETE` for:

- dynamic array indexes;
- unresolved pointee storage;
- aliases whose target differs across paths;
- null/object correlations that require edge predicates to avoid a false temporal finding;
- aggregate copies/initializers/returns or memory-copy transport carrying tracked pointer fields;
- overlapping union pointer storage;
- global and static-local pointer state that can span invocations;
- allocations contained in loops, because allocation-site identity cannot distinguish dynamic instances across iterations;
- pointer-to-integer provenance escapes;
- pointer-valued atomic transport;
- `setjmp`/`longjmp`-style nonlocal control flow;
- unknown calls and pointer-return wrappers;
- `realloc`;
- leaks/owner loss;
- all move/borrow semantics.

This narrowing is intentional. ADR-0010 remains authoritative: false
`INCOMPLETE` is preferable to false `PASS`.

## TEMPORAL RULES

- T002 reports definite or possible use after object destruction when the object/storage relation is modeled.
- T003 enforces single destruction over shared object state.
- destruction through any supported alias changes the authoritative ObjectId state observed by every supported alias.
- `free(NULL)` and pointer clearing remain safe temporal operations; null dereference and leaks are outside P0's claim.

## DIAGNOSTICS / TRACE

JSON findings include `object_id`, optional `access_storage`, and optional
`destroy_storage`. The versioned `cand.check/v1` schema has been updated to
permit those P0.3 fields. Alias trace events now use the actual alias-creation
location instead of reusing the allocation location.

## FIRST INDEPENDENT REVIEW — FINDINGS FIXED

The first review found blocker-class false-PASS paths that were not present in
the original 80-case corpus:

1. **Ambiguous alias target conflated with NULL.** A CFG join where `q` could
   point to two different non-null objects produced `object_id == 0`, the same
   representation used for NULL. `free(q)` or `*q` could therefore silently be
   treated as a null operation. Fixed with separate null and unknown sentinels.
2. **Aggregate pointer transport.** `b = a`, aggregate initialization/return,
   and `memcpy`-style transport could copy tracked pointer fields into new
   untracked storage. These operations now fail closed.
3. **Union overlap.** Different pointer fields of a union were incorrectly
   modeled as independent storages. Union pointer storage is now unsupported
   until a dedicated union/discriminator model exists.
4. **Multidimensional array identity collision.** A single `index` slot could
   collapse `a[0][0]` and `a[1][0]`. Storage identity now records the full
   constant-index path.
5. **Pointer/integer provenance escape.** A tracked pointer converted to an
   integer could bypass the storage graph. Such transport is now INCOMPLETE.
6. **Storage-test oracle weakness.** The harness accepted any non-zero ASan
   execution as confirmation. It now requires successful sanitizer compilation
   and an actual `ERROR: AddressSanitizer` marker for negative fixtures.

Permanent regression fixtures cover each class.

## SECOND INDEPENDENT REVIEW — FINDINGS FIXED

A second clean-room review of the amended head found additional soundness
boundaries:

1. **Allocation-site reuse across loop iterations.** An alias escaping one
   iteration could refer to a destroyed dynamic instance, while the next
   allocation at the same source site reset the shared abstract ObjectId to
   `Owned`. Loop-contained allocations are now explicitly INCOMPLETE in P0.3.
2. **Global/static pointer lifetime.** Per-function state cannot soundly model
   file-scope or static-local pointer state across calls. Ownership-relevant
   operations involving those storages are now INCOMPLETE.
3. **Nullable-alias path correlation.** NULL on one CFG path and an object on
   another is represented as `MaybeNull`. Where nullness and object state are
   correlated in a way P0.3 cannot prove, C& returns INCOMPLETE rather than a
   potentially false T002/T003.
4. **Composite allocation ID stability.** Conditional/comma allocation
   expressions now receive stable synthetic IDs across worklist iterations.
5. **Nonlocal control flow.** `setjmp`/`longjmp` family calls are now explicitly
   unsupported instead of being analyzed as normal calls.
6. **Atomic pointer transport.** Pointer ownership moved through C atomic
   operations is now explicitly unsupported.
7. **Storage-map determinism.** Storage ordering now uses stable source-derived
   keys with an in-process pointer fallback only for pathological equal source
   identities.
8. **Machine contract drift.** `access_storage` and `destroy_storage` were
   emitted by P0.3 but forbidden by the JSON schema's `additionalProperties:
   false`; the schema is now aligned with the implementation.

Permanent regression fixtures cover globals/statics, loop allocation escape,
nullable correlation, nonlocal control flow, atomics, aggregate transport,
union overlap, ambiguous alias joins, multidimensional arrays, and provenance
escape.

## REGRESSION / EVIDENCE

The original P0/P0.1/P0.2 suites remain mandatory. The storage suite compiles
every fixture with ASan and verifies:

- expected PASS -> C& PASS and sanitizer-clean execution;
- expected FAIL -> C& FAIL and an actual ASan error;
- expected INCOMPLETE -> C& exit 3, with no requirement to reshape the program into the current provable subset.

The differential suite continues to reject any `ASan violation + cand PASS`
pair.

## LLM NATURAL APP

The RPG inventory alias showcase demonstrates the core P0.3 win: a local alias
that was an unsupported obligation in P0.2 is now linked to the same ObjectId,
and destruction through one spelling is visible through the other. No source
rewrite is required. Remaining natural-code obligations are intentionally the
next architectural boundaries: interprocedural summaries/contracts, dynamic
storage, global/static state, loop-instance heap abstraction, and later
borrowing semantics.

## CSA COMPARISON

`scan-build` emitted diagnostics on sampled local-alias, struct-member,
constant-array, and conditional-alias UAF fixtures. This remains a scoped
comparison only; C& makes no general superiority claim over Clang Static
Analyzer.

## PERFORMANCE

Original P0.3 measurements for generated translation units containing 1000
functions were approximately: no alias `0.14s` / 76.3 MB RSS; one alias
`0.15s` / 77.7 MB; struct fields `0.17s` / 78.3 MB. The soundness hardening
adds conservative classification and small bookkeeping structures, not a new
whole-program algorithm.

## FINAL REVIEW STATUS

The final review found and closed an unknown pointer-output false-PASS path:
calls such as `make(&q)` now produce `unknown-call-with-pointer-output` even
when `q` is currently NULL. Unknown aggregate-return calls are likewise
reported before their fields can enter the temporal model. Nullable alias
joins continue to produce conservative possible T002/T003 findings, and
known-safe static/string returns remain PASS. Pointer arithmetic that mutates
a tracked storage (`p += 1`, `++p`) now invalidates its binding and reports
`INCOMPLETE` rather than reusing the allocation-base identity. Direct access
to or return of an unmodelled pointer parameter is also explicitly
`INCOMPLETE`.

The original implementation report's “allocation-site identity in loops is
MEDIUM” assessment was too weak: cross-iteration alias escape can create a
false PASS, so it was promoted to a blocker and closed by failing loop
allocations closed. Likewise, aggregate transport, union overlap, ambiguous
alias/null conflation, and cross-call global/static state are now explicit
proof boundaries rather than undocumented holes.

No C&1 soundness claim is introduced. P0.3 remains a deliberately scoped
research verifier whose most important contract is that unsupported ownership
semantics do not silently become PASS.

## RECOMMENDATION

Do not merge on documentation alone. Merge only after the exact final head
passes all repository CI/tests and the final clean-room semantic review finds
no remaining BLOCKER/HIGH correctness issue.
