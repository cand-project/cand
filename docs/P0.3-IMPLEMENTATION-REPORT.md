# P0.3 IMPLEMENTATION REPORT

## Base main

Base: `d47e557` (P0.2 merged main). Implementation commit: `af20afe`.

## ARCHITECTURE

- `ObjectId`: deterministic allocation-site ID (`obj:N`).
- `StorageId`: AST-derived local, field-path, constant-array-element, and reserved dereference-slot identity.
- `PointerRelation`: `Owner`, `Alias`, `Unknown`.
- `ObjectInfo`: authoritative object state, allocation, and destruction metadata.
- `FlowState`: independent object table plus storage-to-object bindings; joins never choose between two non-null object IDs.

## NEWLY SUPPORTED

Local aliases and reassignment, local struct members including nested paths,
constant-index pointer arrays, aliases through those storages, CFG alias joins,
and pointer arithmetic through aliases. Casts that Clang reduces to the same
pointer storage remain supported. Destruction is object-wide.

## STILL INCOMPLETE

Dynamic array indexes (`dynamic-array-storage`), unresolved pointee storage,
ambiguous alias targets, unknown calls, pointer-return wrappers, realloc,
leaks/owner loss, loop instance precision, and all move/borrow semantics.

## TEMPORAL RULES

- T002 reports definite or possible use after object destruction and exposes object, access storage, and destruction storage.
- T003 remains single-destruction enforcement over the shared object state.
- `free(NULL)` and pointer clearing remain safe temporal operations; leaks are out of scope.

## DIAGNOSTICS / TRACE

JSON findings now include `object_id`, `access_storage`, and `destroy_storage`.
Traces include allocation, alias_created, destruction/conditional_destruction,
and access events in deterministic order.

## REGRESSION

`cmake --build build`, all 6 CTest tests, `scripts/check.sh`, and `git diff
--check` pass. The storage suite includes ordinary compiler and ASan checks.
The old P0/P0.1 fixtures whose semantics are now supported were updated from
INCOMPLETE to their intentional PASS/FAIL result.

## ADVERSARIAL REVIEW

80 generated variants (exceeding the 75 requirement): 40 correct PASS, 40
correct FAIL, 0 correct INCOMPLETE, 0 false PASS, 0 false FAIL, 0 analyzer
bugs. Every negative storage fixture was compiled with Clang and confirmed by
ASan; no ASan-confirmed lifetime violation returned C& PASS.

## LLM NATURAL APP

The existing RPG inventory alias showcase is the natural application sample:
P0.2 had one `pointer-alias-initialization` obligation; P0.3 resolves it and
reports the actual T002 violation. No source rewrite was needed. Remaining
obligation categories are external calls, wrapper ownership, dynamic storage,
and future interprocedural contracts.

## CSA COMPARISON

`scan-build` was available and emitted diagnostics on the sampled local-alias,
struct-member, constant-array, and conditional-alias UAF fixtures. This is a
scoped comparison only; no superiority claim is made.

## PERFORMANCE

For generated translation units containing 1000 functions: no alias `0.14s`,
76.3 MB RSS; one alias `0.15s`, 77.7 MB; struct fields `0.17s`, 78.3 MB.

## FINDINGS

BLOCKER: none. HIGH: none. MEDIUM: allocation-site identity is intentionally
imprecise in loops. LOW: alias trace locations reuse allocation locations.

## SAFETY CLAIM

This phase makes no C&1 soundness claim. It preserves the project invariant:
unknown ownership is INCOMPLETE, and false PASS is not accepted.
