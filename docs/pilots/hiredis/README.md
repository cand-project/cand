# C&1/v1 Hiredis integration pilot

This pilot measures how much of pinned Hiredis can be qualified by the
existing C&1/v1 verifier using reviewed metadata only. It does not change C&1
semantics, the public claim, or the upstream Hiredis source.

## Pinned inputs

- C& protected-main starting commit: `74adeaddbe42d3d34c1d0a26f7854871d890b7c8`
- Hiredis: `redis/hiredis@33a12fb23531f33e3455c7ed46008c20c7ad9c78`
- Redis test server: `redis/redis@5f08991bce470ab721f10d7f815baad49f3aae60`
- qualified environment: Ubuntu 24.04, x86_64, Clang 18.1.3, C11

The H0 result is immutable and is retained as the zero-metadata control:
5,509 representative C LOC, 370 PASS, 0 FAIL, 5,139 INCOMPLETE, zero
annotations, zero contracts, and zero confirmed false PASS.

## Scope and reproduction

The common C& scope is the seven compilable translation units `alloc.c`,
`async.c`, `hiredis.c`, `net.c`, `read.c`, `sds.c`, and `sockcompat.c`. The
async files are measured but callback retention remains excluded and fail
closed. The full command details and measured outputs are in
`HIREDIS-INTEGRATION-RESULTS.md`.

The ordinary upstream build is CMake/Ninja with Clang 18. The ordinary test is
CTest with the pinned Redis server on `PATH`. The sanitizer control uses
`-fsanitize=address,undefined -fno-omit-frame-pointer` and reports CTest 1/1
PASS with no findings.

The pinned checkout contains 25 C translation units and 27 headers. A
reproducible `compile_commands.json` can be generated by adding
`-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` to the CMake configure command. The
pilot used the equivalent deterministic seven-file scope and explicit C11
flags so that C& diagnostics were comparable across H0-H3. Baseline build
artifacts include `libhiredis.so.1.5.0` and `hiredis-test`.

The contract bundle is pilot-scoped and requires maintainer review before it
is treated as an accepted trust input. It is not global C& policy.

## Status

The pilot has zero confirmed false PASS and unchanged ordinary ABI/layout and
exported-symbol results. H1, H2, and H3 did not increase coverage over H0;
the dominant blockers remain external ownership, pointer storage/aliasing,
and cross-translation-unit effects. Therefore this is evidence for adoption
ergonomics and future work, not a reason to broaden C&1/v1 or start C&2.
